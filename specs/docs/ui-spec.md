# UI 명세

## 1. 개요

### 목적

Ask Teacher는 사용자가 질문을 작성하고 다른 사용자의 질문을 조회할 수 있는 Q&A 서비스다.

본 문서는 웹 화면의 구성, 사용자 동작, 화면 전환 및 공통 UI 처리 기준을 정의한다.

### 관련 공식 명세

- [공통 요구사항](requirements.md)
- [API 명세](openapi.yaml)
- [인증 정책](auth-policy.md)
- [ERD](schema.dbml)

API 요청·응답 구조, 데이터 검증 및 인증·인가 규칙은 각 공식 명세를 따른다.

본 문서는 React 컴포넌트, 상태 관리 라이브러리, API 함수명 등 구체적인 구현 방식을 규정하지 않는다.

기능의 구현 진행 상태는 GitHub Issue 및 PR에서 관리한다.

---

## 2. 사용자 유형

### 비로그인 사용자

- 회원가입 및 로그인 화면에 접근할 수 있다.
- 게시글 목록과 상세 내용을 조회할 수 있다.
- 카테고리와 게시글별 댓글을 조회할 수 있다.

### 로그인 사용자

- 비로그인 사용자의 조회 기능을 이용할 수 있다.
- 질문 게시글을 작성할 수 있다.
- 본인이 작성한 게시글을 수정하거나 삭제할 수 있다.
- 댓글 작성·수정·삭제 및 좋아요 등 인증이 필요한 기능을 이용할 수 있다.

### 관리자

- 현재 별도의 관리자 전용 화면은 정의하지 않는다.

## 3. 화면 및 라우팅

| 화면 | 경로 | 설명 |
|---|---|---|
| 게시글 목록 | `/posts` | 질문 목록 조회 |
| 게시글 작성 | `/posts/create` | 질문 작성 |
| 게시글 상세 | `/posts/:postId` | 질문 상세 조회 |
| 게시글 수정 | `/posts/:postId/edit` | 기존 질문 수정 |
| 로그인 | `/login` | 로그인 |
| 회원가입 | `/signup` | 계정 생성 |

위 경로는 기존 Frontend 요구사항에서 정의한 화면 경로를 기준으로 한다.

신규 기능의 화면과 경로는 관련 Parent Issue에서 구체화한 후 본 문서에 반영한다.

## 4. 공통 레이아웃 및 UI 동작

### 헤더 및 이동

- 서비스명과 주요 탐색 메뉴를 제공한다.
- 서비스명 클릭 시 게시글 목록 또는 홈 화면으로 이동한다.
- 로그인 및 회원가입 화면으로 이동할 수 있는 수단을 제공한다.
- 현재 사용자 인증 상태에 따른 메뉴 표시 정책은 별도 기능 결정에 따른다.

### 공통 상태 처리

- 데이터를 불러오는 동안 로딩 상태를 표시한다.
- 조회 결과가 없는 경우 적절한 빈 데이터 메시지를 표시한다.
- 요청 실패 시 사용자가 이해할 수 있는 오류 메시지를 표시한다.
- 목록과 선택지처럼 독립적으로 조회하는 데이터는 각각의 로딩·오류 상태를 표시한다. 재시도를 제공할 때는 실패한 조회의 조건을 유지한다.
- 작성·수정·삭제 등 중복 제출이 문제가 되는 작업은 요청 중 반복 실행을 방지한다.
- 입력값 검증 실패 시 서버 요청 전에 사용자에게 해당 문제를 안내한다.
- 서버 오류 발생 시 작성 중인 입력값은 가능한 한 유지한다.

## 5. 게시글 목록 화면

**경로:** `/posts`

### 화면 구성

- 게시글 목록
- 게시글 제목
- 작성자 닉네임
- 생성일
- 새 글 표시
- 게시글별 좋아요 수
- 새 글 작성 화면으로 이동하는 버튼
- 검색어 입력, 전체 또는 개별 카테고리 선택, 검색 버튼을 포함한 검색 폼
- 처음·이전·페이지 번호·다음·마지막 이동과 현재 페이지 표시

### 사용자 동작

- 로그인 여부와 관계없이 화면 진입 시 `GET /api/posts`로 목록을 조회하고 `GET /api/categories`로 카테고리 선택지를 불러온다.
- 로그인 여부와 관계없이 목록 응답의 `likeCount`를 게시글별로 표시한다.
- 게시글 제목을 클릭하면 해당 게시글 상세 화면으로 이동한다.
- 새 글 작성 버튼을 클릭하면 게시글 작성 화면으로 이동한다.
- 새 글 여부가 참인 게시글에는 `new` 표시를 노출한다.

### 검색 조건 적용과 URL 복원

- 기본 조회 조건은 검색어 없음, 전체 카테고리, 첫 페이지다. 검색어는 제목 또는 내용에 적용한다. 공백만 입력하면 검색어가 없는 것으로 처리한다. 개별 카테고리와 검색어를 함께 적용할 수 있다.
- 검색 버튼을 누르거나 Enter로 폼을 제출하면 입력한 검색어와 선택한 카테고리를 함께 적용하고 첫 페이지를 조회한다. 제출 전에는 입력이나 선택을 바꿔도 적용 조건·페이지·목록을 유지한다.
- 적용한 검색어·카테고리·페이지는 `/posts`의 URL 쿼리에 유지한다. 직접 방문, 공유 링크 열기, 새로고침과 브라우저 뒤로·앞으로 가기에서는 URL을 기준으로 입력값과 선택값을 복원하고 해당 페이지와 결과를 표시한다.

### 페이지 이동

- 목록은 응답의 `content`를 서버가 반환한 최신순으로 표시한다. 페이지 이동 범위는 응답의 페이지 메타데이터를 사용한다. 화면의 페이지 번호는 1부터 표시하고 API에는 0부터 시작하는 `page`를 보낸다. 페이지 크기는 API 기본값인 10을 사용한다.
- 페이지를 이동할 때는 마지막으로 적용한 검색어와 카테고리를 유지한다. 첫 페이지에서는 처음·이전, 마지막 페이지에서는 다음·마지막을 비활성화한다. 결과가 0건이거나 한 페이지에 모두 표시되면 다른 페이지로 이동할 수 없다.
- URL의 페이지 값이 없거나 잘못된 경우 첫 페이지를 사용한다. 유효한 페이지 번호가 결과 범위를 넘으면 마지막 유효 페이지를 조회한다. 0건이면 첫 페이지를 기준으로 빈 결과를 표시한다. 보정한 페이지는 URL과 화면에 함께 반영한다.

### 로딩·빈 결과·오류

- 목록과 카테고리 선택지를 불러오는 동안 각 영역에 로딩 상태를 표시한다.
- 목록 조회가 성공해 0건이면, 적용 조건이 없을 때는 “게시글이 없습니다.”를 표시하고 적용 조건이 있을 때는 검색 조건에 맞는 게시글이 없음을 안내한다.
- 목록 조회에 실패하면 오류를 표시하고 마지막으로 적용한 검색어·카테고리·페이지로 재시도할 수 있게 한다. 요청 실패는 빈 결과 메시지로 표시하지 않는다.
- 카테고리 선택지 조회에 실패하면 선택지 오류와 재시도를 별도로 제공한다. 카테고리 조건 없이 목록을 조회하는 흐름은 유지한다.
- 삭제되었거나 존재하지 않는 카테고리로 목록을 요청해 `404`를 받으면 해당 카테고리를 사용할 수 없음을 안내하고, 전체 카테고리를 선택해 다시 검색할 수 있게 한다.

## 6. 게시글 작성 화면

**경로:** `/posts/create`

### 화면 구성

- 카테고리 선택
- 제목 입력
- 내용 입력
- 첨부파일 선택과 선택한 파일 목록
- 작성 버튼

### 사용자 동작

- 화면 진입 시 선택 가능한 카테고리를 조회한다.
- 사용자는 카테고리, 제목, 내용을 입력한다.
- 제목은 필수이며 최대 100자다.
- 내용은 필수이며 최대 5000자다.
- 제목과 내용은 공백만 입력할 수 없다.
- 입력값 검증에 실패하면 요청을 보내지 않고 경고 메시지를 표시한다.
- 작성 중에는 중복 제출을 방지한다.
- 작성 성공 시 성공 안내 후 `/posts`로 이동한다.
- 작성 실패 시 오류 메시지를 표시한다.

### 첨부파일 선택과 제출

- 첨부파일 없이 게시글을 작성하거나 JPEG, PNG, WebP 이미지와 PDF를 여러 개 첨부할 수 있다.
- 파일을 선택하면 API 명세의 지원 형식과 빈 파일 여부를 검사한다. 지원하지 않는 형식이나 빈 파일은 선택 목록에 추가하지 않고 이유를 안내한다.
- 선택한 파일의 이름을 목록에 표시한다. 제출 전에는 새로 선택한 파일을 목록에서 개별 제거할 수 있다.
- 작성 요청에는 선택 목록에 남은 파일을 첨부한다. 요청을 처리하는 동안 중복 제출을 막는다.
- 화면에 고정 용량 수치를 표시하지 않는다. 서버가 용량 초과를 반환하면 카테고리·제목·내용과 선택 목록을 유지하고 오류를 안내한다.

## 7. 게시글 상세 화면

**경로:** `/posts/:postId`

### 화면 구성

- 제목
- 내용
- 작성자 닉네임
- 카테고리
- 생성일
- 수정 화면 이동 버튼
- 삭제 버튼
- 좋아요 수와 하트 버튼

### 사용자 동작

- URL의 게시글 ID에 해당하는 정보를 조회한다.
- 존재하지 않거나 조회할 수 없는 게시글은 오류 상태를 표시한다.
- 수정 버튼을 클릭하면 게시글 수정 화면으로 이동한다.
- 삭제 버튼을 클릭하면 삭제 확인 절차를 시작한다.

### 게시글 첨부파일

- 첨부된 이미지는 본문 아래에 표시한다. PDF는 ‘PDF 첨부 1’처럼 파일 유형과 순번을 표시한 링크로 제공하고, 선택하면 새 탭에서 연다.
- 상세 화면에는 첨부파일의 원본 파일명과 저장 파일명을 표시하지 않는다.
- 첨부파일이 없거나 파일을 표시하지 못해도 게시글 본문을 읽을 수 있어야 한다.

### 게시글 댓글

- 게시글 본문과 별도로 댓글 영역을 표시한다. 로그인 여부와 관계없이 댓글 목록과 댓글별 좋아요 수를 볼 수 있다. 댓글 목록의 로딩, 빈 결과, 오류와 재시도를 댓글 영역에서 처리하고, 댓글 조회에 실패해도 게시글 본문은 읽을 수 있다.
- 목록은 서버의 최신순 결과를 기본으로 표시한다. 좋아요순을 선택할 수 있으며 이전·다음 버튼으로 페이지를 이동한다. 정렬을 변경하면 첫 페이지(`page=0`)부터 조회한다.
- 비로그인 상태에서 댓글 작성이나 좋아요를 시도하면 현재 게시글과 URL을 유지하고 로그인 필요 안내와 `/login` 링크를 표시한다. 변경 요청은 보내지 않으며, 사용자가 링크를 선택하면 로그인 화면으로 이동한다. 안내와 링크는 키보드로 이용할 수 있다.
- 로그인 사용자는 댓글을 작성하고 좋아요를 등록·취소할 수 있다. 현재 인증 세션의 유효한 사용자 ID와 댓글 응답의 유효한 `writerId`가 일치할 때만 수정·삭제 조작을 표시한다. 사용자 ID를 확인할 수 없거나 조회 결과의 세션이 바뀌면 해당 조작을 숨긴다. 변경 요청의 최종 인가는 서버가 처리한다.
- 작성·수정 시 공백만 있는 입력과 1,000자 초과 입력을 검증한다. 변경 요청을 처리하는 동안 같은 동작의 중복 실행을 막고, 작성·수정이 실패하면 입력을 유지하고 오류를 표시한다.
- 작성·수정·삭제에 성공하면 현재 페이지를 다시 조회한다. 새 댓글이 현재 페이지에 보이지 않을 수 있으므로 작성 성공을 안내한다. 삭제로 현재 페이지가 사라지면 마지막 유효 페이지를 조회한다. 댓글이 모두 사라지면 첫 페이지에서 빈 결과를 표시한다.
- 좋아요 등록·취소에 성공하면 현재 페이지를 다시 조회해 좋아요 수, 내 좋아요 상태와 서버 정렬 순서를 반영한다. 중복 등록, 취소 대상 없음, 응답 유실 등으로 결과를 확신할 수 없으면 서버에서 현재 상태를 확인하고 그 결과를 바탕으로 재시도할 수 있게 한다.
- 로그인·로그아웃·계정 전환 후 이전 세션의 작성자 표시, 내 좋아요 상태, 지연 응답으로 현재 댓글 화면을 갱신하지 않는다.

### 게시글 좋아요

- 로그인 여부와 관계없이 상세 응답의 `likeCount`를 표시한다. 로그인 사용자의 하트는 현재 세션의 상세 응답에 있는 `likedByMe`에 따라 채우거나 비운다. 버튼의 접근 가능한 이름과 눌림 상태로 좋아요 상태를 전달한다.
- 로그인 사용자가 하트 버튼을 누르면 현재 상태에 따라 좋아요를 등록하거나 취소한다. 요청을 처리하는 동안 중복 실행을 방지한다. 성공하면 해당 게시글 상세와 목록을 다시 조회해 하트와 좋아요 수를 서버 값으로 갱신한다.
- 비로그인 사용자가 하트 버튼을 누르면 현재 게시글과 URL을 유지하고 ‘좋아요를 누르려면 로그인해 주세요’라는 안내와 로그인 링크를 표시한다. 이 클릭은 등록·취소 요청을 보내지 않는다. 안내와 링크는 키보드와 스크린 리더로 이용할 수 있으며, 링크를 선택하면 기존 로그인 화면(`/login`)으로 이동한다.
- 요청이 실패하면 오류를 안내하고 성공 상태를 표시하지 않는다. 중복 등록, 취소 대상 없음, 응답 유실 등으로 현재 상태를 확신할 수 없으면 상세를 다시 조회하고 확인된 상태에서 재시도할 수 있게 한다. 게시글 없음과 인증 실패·장애는 기존 상세 화면과 세션 처리 기준을 적용한다.
- 로그인·로그아웃·계정 전환 후 이전 세션의 좋아요 상태나 지연 응답으로 현재 상세 화면을 갱신하지 않는다.

### 작성자 표시와 인증 상태

- 현재 인증 상태에 해당하는 상세 응답의 `isAuthor`가 `true`일 때만 수정·삭제 버튼을 표시한다. 닉네임 비교로 작성자를 판단하지 않는다.
- 응답을 확인하는 중이거나 구버전 서버 응답에 `isAuthor`가 없으면 버튼을 숨긴다. 화면 표시가 수정·삭제 요청의 서버 인가를 대신하지 않는다.
- 로그인·로그아웃·계정 전환 시 이전 상세 조회 결과를 폐기하고 현재 인증 상태로 다시 조회한다. 이전 사용자의 작성자 표시를 재사용하지 않는다.
- 상세 조회의 `401`에는 기존 인증 정책과 세션 복구 흐름을 적용한다. 복구가 거부되거나 응답이 유실돼 실패하면 재로그인을 안내하고, 인증 없이 상세를 다시 조회해 게시글을 보여준다. 이때 수정·삭제 버튼은 숨긴다.
- 인증 서비스의 `503`은 장애를 안내하고 재시도를 제공한다. 장애를 세션 만료로 단정하거나 자동으로 비로그인 성공으로 처리하지 않는다.

## 8. 게시글 수정 화면

**경로:** `/posts/:postId/edit`

### 화면 구성

- 기존 카테고리 선택값
- 기존 제목
- 기존 내용
- 저장된 첨부파일 목록과 새로 선택한 파일 목록
- 첨부파일 선택
- 수정 버튼

### 사용자 동작

- 화면 진입 시 기존 게시글 정보와 카테고리 목록을 조회한다.
- 기존 입력값을 수정 가능한 상태로 표시한다.
- 제목과 내용은 작성 화면과 동일한 입력 검증 규칙을 따른다.
- 검증에 실패하면 수정 요청을 보내지 않는다.
- 수정 요청 중에는 중복 제출을 방지한다.
- 수정 성공 시 `/posts/:postId` 상세 화면으로 이동한다.
- 수정 실패 시 오류 메시지를 표시하고 입력값을 유지한다.

### 첨부파일 확인과 추가

- 저장된 첨부파일을 화면에 표시하고 수정 후에도 유지한다. 저장된 첨부파일에 대한 개별 삭제·교체 조작은 제공하지 않는다.
- 새 파일을 선택하고 제출 전 목록에서 개별 제거할 수 있다. 지원 형식과 빈 파일 검사, 파일명 표시, 용량 초과 안내는 작성 화면과 같은 규칙을 따른다.
- 수정 요청에는 새로 선택한 목록에 남은 파일만 첨부한다. 서버가 용량 초과를 반환하면 수정 중인 카테고리·제목·내용과 선택 목록을 유지한다.

## 9. 게시글 삭제 기능

**사용 화면:** 게시글 상세

### 사용자 동작

- 삭제 버튼을 클릭하면 삭제 확인 대화상자를 표시한다.
- 확인하면 삭제 요청을 실행한다.
- 취소하면 요청 없이 기존 화면에 머문다.
- 삭제 요청 중에는 중복 실행을 방지한다.
- 삭제 성공 시 `/posts`로 이동한다.
- 삭제 실패 시 오류 메시지를 표시한다.

## 10. 회원가입 화면

**경로:** `/signup`

### 화면 구성

- 이메일 입력
- 비밀번호 입력
- 닉네임 입력
- 회원가입 버튼

### 사용자 동작

- 이메일 형식과 필수 입력 여부를 검증한다.
- 비밀번호는 최소 8자여야 한다.
- 닉네임은 2자 이상 20자 이하여야 한다.
- 검증 실패 시 요청을 보내지 않는다.
- 회원가입 요청 중에는 중복 제출을 방지한다.
- 회원가입 실패 시 화면을 유지하고 오류를 안내한다.
- 회원가입 성공 시 게시글 목록 화면으로 이동한다.

최종 입력 검증과 중복 확인 규칙은 공식 API 명세를 따른다.

## 11. 로그인 화면

**경로:** `/login`

### 화면 구성

- 이메일 입력
- 비밀번호 입력
- 로그인 버튼

### 사용자 동작

- 이메일 형식 및 필수 입력 여부를 검증한다.
- 로그인 버튼 클릭 시 인증 요청을 실행한다.
- 로그인 실패 시 오류 메시지를 표시한다.
- 로그인 성공 시 게시글 목록 화면으로 이동한다.

### 인증 연계

- Access Token, Refresh Token, CSRF 및 재발급 정책은 공식 API 명세를 따른다.
- 인증 상태를 사용하는 화면과 보호된 기능은 서버의 인증·인가 규칙과 일치해야 한다.
- 자동 재발급, 탭 간 인증 상태 동기화 및 인증 만료 시 화면 처리의 구체적인 UX는 관련 Issue에서 결정한다.

## 13. 명세 관리 원칙

1. 사용자에게 제공할 화면과 동작은 이 문서에서 정의한다.
2. API·인증·데이터 구조는 Specs의 해당 공식 명세를 따른다.
3. 개별 기능의 미결정 사항과 승인 이력은 Parent Issue에서 관리한다.
4. React 내부 구현 설계와 작업 이력은 Frontend Issue 및 개발 문서에서 관리한다.
5. 문서 변경이 필요한 경우 관련 영향 범위를 검토하고 승인된 내용만 반영한다.
6. 기능 완료 여부는 이 문서의 체크박스가 아닌 Issue·PR·검증 결과로 판단한다.
